# 核心稳定性修复：设计

> 状态：已确认；对应 [`20260912-核心稳定性修复-需求.md`](20260912-核心稳定性修复-需求.md)。

## 当前实现与问题

当前 Loan Handler 直接完成解析、校验、签名、Mongo 查询和错误转换。Mongo 客户端由 `sync.Once`
管理，数据解析允许部分成功；SID 共享 `math/rand.Rand`；主程序先关 Mongo 再排空 HTTP。

## 方案

### SID 与签名

- 使用 `crypto/rand` 生成 SID 随机部分，通过拒绝采样保持原字符集和长度，生成失败显式返回错误。
- `GenerateSID`、`GenerateRandomID` 返回 `(string, error)`；Handler 将极低概率的随机源失败转换为
  HTTP `500` + `ErrInternalError`。
- 保留现有 MD5 签名内容和大小写兼容，只用 `crypto/subtle.ConstantTimeCompare` 替代普通比较。

### Mongo 客户端生命周期

- 用互斥锁保护客户端发布与关闭；连接和 Ping 全部成功后才把候选客户端发布为全局客户端。
- 首次初始化失败不缓存失败状态，后续调用可以重试；失败候选客户端立即断开。
- 提取包内连接函数变量作为测试接缝，生产默认仍调用现有 Mongo Driver，不增加依赖。
- `Close` 在锁内取出并清空客户端，在锁外断开；关闭后允许未来重新初始化。

### 数据与错误

- 定义 `ErrNotFound`、`ErrInvalidData`、`ErrUnavailable` 三个可通过 `errors.Is` 判断的包级错误。
- Mongo Driver 的 `ErrNoDocuments` 转为 `ErrNotFound`；Context deadline/cancel 原样保留；其他连接或
  查询错误转为 `ErrUnavailable`；gzip/字段错误转为 `ErrInvalidData`。
- 数据必须恰好六项且全部可解析为整数，否则整体失败，不返回部分 map。

### HTTP Handler

- 使用具体请求 DTO：string、int、int64，让 JSON 解码直接拒绝小数、字符串和溢出数字。
- 保留公开 `Create`，内部增加接收查询函数的实现作为测试接缝，不新增空壳业务层。
- 错误映射按已确认契约执行，响应消息只来自 `rescode`，详细错误写入项目 logger。
- SID 只在请求参数和签名校验通过后生成，失败响应不生成无用 SID。

### 关闭顺序

- 提取可测试的关闭编排函数；始终先调用 HTTP Shutdown，再调用 Mongo Close。
- 即使 HTTP Shutdown 返回错误，也尝试关闭 Mongo，并用 `errors.Join` 返回全部关闭错误。

## 测试设计

- `pkg/utils`：SID 格式/失败/并发，签名兼容与错误签名。
- `pkg/mongo`：严格六字段、坏 gzip、not-found/error 包装、初始化失败后重试和并发发布。
- Loan Controller：小数/字符串参数拒绝，四类错误映射与安全消息，成功响应。
- `main`：关闭调用顺序及双错误保留。
- `routes`/`middleware`：Health 路由和限流/CORS 的关键现有边界。

测试不连接真实 Mongo、Redis 或外部服务，不运行数据初始化 CLI。

## 兼容与回滚

- 成功请求/响应、字段名、签名生成字符串保持不变。
- 错误 HTTP/业务码按已确认需求发生变化；若调用方不兼容，可回滚 Handler 错误映射提交，底层可判定
  错误和数据完整性修复仍可保留。
- SID 函数签名是 Go 包级 API 变化，但仓库内只有 Loan Handler 和测试调用；未发现外部 Go module
  消费证据。外部消费者如存在属于待确认风险。

## 残余风险

- 五分钟签名重放窗口仍存在；修复需要 nonce/幂等状态及公开契约，另行设计。
- Mongo 全局客户端仍是进程级状态，未改为完整依赖注入。
- 本次不处理完整 Body 日志和 API Key 真实性鉴权，它们仍是 P0 风险。
