# 核心稳定性修复：需求

> 状态：已确认并实施；来源为 2026-09-12 用户要求修复审计问题 3–10。

## 背景与事实来源

当前 `POST /loan` 调用链存在以下已由源码确认的问题：

- `pkg/utils/sid.go` 在并发 Handler 间共享非并发安全的 `math/rand.Rand`；
- `pkg/mongo/mongo.go` 用 `sync.Once` 固化首次 Mongo 连接结果，首次失败后不能恢复；
- `main.go` 关闭时先断开 Mongo，再排空 HTTP 请求；
- Loan Handler 把 Mongo 未查得、超时、不可用和数据损坏都返回为 HTTP `200` + `3001`，并暴露原始错误；
- Mongo 解压结果字段不足或整数解析失败时会返回部分数据和成功响应；
- Loan 请求通过 `interface{}` 接收数字，小数可在转为整数时被静默截断；
- 签名使用普通字符串比较，且现有五分钟时间窗口内没有防重放状态；
- Controller、路由、中间件、Mongo、配置和主程序当前缺少直接自动化测试，核心业务覆盖不足。

事实来源：`main.go`、`app/Http/controllers/loan/index.go`、`pkg/mongo/mongo.go`、
`pkg/utils/sid.go`、`pkg/utils/signature.go` 及相关现有测试。

## 目标

在不增加生产依赖、不改变成功响应字段、不改变现有 MD5 签名生成规则的前提下，修复上述可在
当前契约内确定的并发、恢复、关闭、错误治理、数据完整性、输入解析和签名比较问题，并用自动化
测试防止回归。

## 范围

1. SID 改用并发安全、适用于标识符生成的随机源；保留 prefix、长度和字符集契约。
2. Mongo 客户端只有成功 Connect + Ping 后才缓存；初始化失败允许后续调用重试；关闭后状态可安全清理。
3. Graceful Shutdown 先停止接收并排空 HTTP 请求，再关闭 Mongo。
4. Mongo 数据访问返回可判定错误，Handler 对外只返回稳定文案，不返回驱动、DSN 或解压原始错误。
5. Mongo 解压结果必须恰好包含六个合法整数，否则整体失败，不返回部分成功结果。
6. `phone`、`pcode`、`apikey`、`timestamp`、`sign` 使用明确请求类型；`pcode` 和 `timestamp`
   的小数、字符串及溢出值必须拒绝。
7. 签名验证改用常量时间比较，但继续接受现有大小写兼容行为并保持签名算法不变。
8. 为以上行为新增单元或组件测试，并覆盖 `/health`、Loan 参数/错误路径和相关中间件边界。
9. 执行格式、静态检查、全量测试、竞态测试和构建；当前没有团队确认的覆盖率百分比门槛，
   不为制造数字而添加低价值测试。

## 拟定错误契约

用户已确认采用下表契约：

| 场景 | HTTP | `status` | 对外消息来源 |
| --- | ---: | ---: | --- |
| Mongo 文档不存在 | 200 | 3001 `ErrDataNotFound` | `rescode.GetCodeMsg` |
| 请求 Context 或 Mongo 查询超时 | 504 | 9003 `ErrTimeout` | `rescode.GetCodeMsg` |
| Mongo 连接、Ping 或查询依赖不可用 | 503 | 9002 `ErrServiceUnavailable` | `rescode.GetCodeMsg` |
| gzip 损坏、字段数错误或字段不是整数 | 500 | 9001 `ErrInternalError` | `rescode.GetCodeMsg` |

所有详细原因只进入内部日志，且不得包含密钥、连接凭据或完整请求/响应 Body。

## 非目标

- 不实施仍为草案的 API Key 三层账号鉴权方案。
- 不更换 MD5 签名算法，不增加请求字段，不改变参数排序和签名字符串格式。
- 不实现 nonce、请求 ID 幂等存储或分布式防重放；这需要公开请求契约和状态存储决策。
- 不重构完整 Controller/Service/Repository 架构，不清理 Redis、gRPC 或其他遗留模块。
- 不调整 CORS、限流、README、CI、部署和性能策略；允许为现有中间件行为增加测试。

## 技术与项目结构

- Go `1.24.0`、toolchain `go1.24.10`、Gin `1.11.0`；不新增依赖。
- 预计修改：`main.go`、Loan Handler、`pkg/mongo`、`pkg/utils` 及对应测试。
- 测试沿用 Go 标准 `testing`；HTTP 组件测试使用标准库 `httptest` 和现有 Gin。为隔离 Mongo，
  允许对 Loan Handler 做最小可测试性接缝，但不新增空壳 Service/Repository 层。
- Go 代码遵循 `gofmt`，错误用 `errors.Is` 和 `%w` 保留可判定链路。

## 可测试验收标准

- 100 个以上 goroutine 并发生成 SID 时无 race，长度、前缀和字符集保持不变。
- 模拟第一次 Mongo 初始化失败后，第二次调用能够重新初始化；并发初始化只发布一个成功客户端。
- Shutdown 的可测试编排顺序为 HTTP 排空在前、Mongo 关闭在后。
- 未查得、超时、依赖不可用和损坏数据分别得到拟定错误契约，响应不包含原始底层错误。
- 少于/多于六项、空项、非整数、损坏 gzip 均不能产生成功结果。
- `pcode=10001.5`、字符串数字、超范围值，以及小数/字符串 timestamp 均返回参数错误。
- 现有合法签名继续通过，错误签名失败，比较使用常量时间实现。
- `/health`、Loan Handler 的关键参数与错误转换、相关中间件边界具有直接自动化测试；新增测试能在
  移除对应修复后失败，而不是只提高行覆盖数字。
- 全量格式、静态检查、测试、竞态测试和构建通过。

## 边界

- 总是：先添加可复现失败测试，再做最小修复；保留当前未提交的纯 `gofmt` 修改。
- 先确认：本文件错误 HTTP/业务码表；任何签名请求契约或算法变化。
- 禁止：运行 Mongo 初始化 CLI；连接真实外部服务；记录或提交凭据；删除现有测试；自动 Commit。

## 已确认决策

1. 采用“未查得 200/3001、超时 504/9003、依赖不可用 503/9002、数据损坏 500/9001”。
2. 问题 9 本轮只修复常量时间比较；防重放留给后续独立契约 Spec。
